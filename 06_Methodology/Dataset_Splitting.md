## 1. Five Lethal Data Leakage Pathways & Their Systematic Prevention

A systematic review of the Phase 01 corpus (`Paper01`, `Paper06`, `Paper08`, `Paper22`) revealed five widespread data leakage defects in educational data mining. PRIE defines explicit mathematical partitioning mechanisms to prevent each defect:

├────┬─────────────────────┬──────────────────────────┬───────────────────────────┤

├────┼─────────────────────┼──────────────────────────┼───────────────────────────┤

## 2. Partitioning Strategies by Dataset Modality

---

### Strategy 1: Stratified Student-Level Split (Static Tabular: DS-BENCH-01, DS-SYNTH-01)
- **Protocol**: Stratified 80 / 10 / 10 Train-Validation-Test Split.
- **Stratification Objective**: Preserves the exact ratio of the target placement label ($y \in \{0, 1\}$) across all three partitions:
  $$rac{N_{	ext{placed}}^{(	ext{train})}}{N_{	ext{unplaced}}^{(	ext{train})}} pprox rac{N_{	ext{placed}}^{(	ext{val})}}{N_{	ext{unplaced}}^{(	ext{val})}} pprox rac{N_{	ext{placed}}^{(	ext{test})}}{N_{	ext{unplaced}}^{(	ext{test})}}$$
- **Secondary Stratification**: When sample size allows ($N \ge 1,000$), stratification is performed across joint strata: $(	ext{Target Class} 	imes 	ext{Department Specialization})$.

---

### Strategy 2: GroupKFold Partitioning (Multi-Modal Resumes: DS-CORPUS-01)
- **Protocol**: 5-Fold Grouped Split grouped by `Author_UUID`.
- **Methodological Rule**: Many students maintain multiple resume revisions (e.g., Software Engineering draft vs Data Science draft). Standard random splitting places Revision 1 in Train and Revision 2 in Test, causing catastrophic near-duplicate feature memorization.
- **Enforcement**: GroupKFold guarantees that **all document revisions generated by a given individual are assigned exclusively to either the Training fold or the Testing fold**.

---

### Strategy 3: Rolling-Origin Temporal Split (Longitudinal Telemetry: DS-BENCH-02)
- **Protocol**: Forward-Chaining Rolling-Origin Backtesting.
- **Methodological Rule**: In longitudinal time-series forecasting, randomly shuffling time intervals violates temporal causality and fabricates artificial predictive accuracy.
- **Mathematical Formulation**:
  $$	ext{Fold } k: \quad 	ext{Train} = [t_1, t_k], \quad 	ext{Validation} = [t_{k+1}, t_{k+h}], \quad 	ext{Test} = [t_{k+h+1}, t_{k+2h}]$$
  where $h$ is the prediction horizon ($h = 6$ months or $12$ months). The model is strictly evaluated on future time intervals it has never observed.

```
Time ──►
Split 1: [── Train (W01–W08) ──][─ Val (W09–W10) ─][─ Test (W11–W12) ─]
Split 2: [──── Train (W01–W10) ────][─ Val (W11–W12) ─][─ Test (W13–W14) ─]
Split 3: [────── Train (W01–W12) ──────][─ Val (W13–W14) ─][─ Test (W15–W16) ─]
```

## 3. The Isolation Protocol for Test Sets

1. **Partitioning at Ingress**: Dataset splitting occurs immediately following data ingestion and schema validation.
2. **Test Set Freezing**: Test data is serialized into a standalone file `test_split.parquet`, sealed with a SHA-256 cryptographic hash, and flagged read-only.
3. **Zero-Touch Mandate**: The test set is strictly sequestered during:
   - Missing value imputation modeling (MICE).
   - Outlier boundary detection (Tukey IQR).
   - Normalization scaling (RobustScaler).
   - Class imbalance oversampling (SMOTE).
   - Hyperparameter Bayesian optimization (Optuna).
   - Model feature selection (RFECV).
4. **Final Benchmarking Execution**: The test set is ingested exactly once by the frozen pipeline during Phase D of the Research Workflow (`Research_Workflow.md`).
